# EchoWreck

Изометрический 3D‑прототип на **Godot 4.6** (Jolt Physics). Сейчас это «песочница выживания + крафт + черновой бой»: движение, добыча, инвентарь, станции, статы, меч по дуге, враги в пещере, переходы между уровнями с сохранением состояния мира. Визуал мира и многих объектов — заглушки: без полноценного рельефа, дорожек, травы и финальных моделей; см. чеклист **«Мир: арт, ландшафт, поверхности»**. Смысл петель добычи и возобновления ресурсов — в разделе **«Геймплей: задумка»**.

## Запуск

Открыть проект в Godot 4.6+. Стартовая сцена: **`scenes/ui/main_menu/main_menu.tscn`**. Основной уровень — `scenes/main.tscn`, тестовая пещера — `scenes/levels/cave_test.tscn`. Меню паузы и экран смерти подвешиваются на игрока из кода.

### Переходы между уровнями

**Где лежат уровни**

| Путь | Что там |
|------|---------|
| `res://scenes/levels/` | Отдельные локации (пещеры, данжи, деревни…) — **сюда добавляйте новые `.tscn`** |
| `res://scenes/main.tscn` | Основной хаб / поляна (можно позже перенести в `levels/`) |
| `res://resources/world/level_registry.tres` | Каталог id → сцена (для обзора и опциональной привязки в зонах) |

Подробнее: `scenes/levels/README.md`.

**Узлы (видны в редакторе — цветные объёмы и подписи)**

| Сцена | Назначение |
|-------|------------|
| `level_spawn_point.tscn` | Синяя «стрелка» + подпись `portal_id`. Куда ставится игрок при входе **с этого id**. |
| `level_transition_zone.tscn` | Зелёный полупрозрачный бокс (`zone_size`). Куда ведёт переход. |
| `level_portals_container.tscn` | Пустой `Node3D` — папка для порядка (инстанс как `LevelPortals`). |

В инспекторе у зоны: **`target_level`** (перетащить PackedScene) и **`arrival_portal_id`** (id маркера на целевой сцене).  
Несколько зон на одном уровне → одна и та же `target_level`, но **разные** `arrival_portal_id`.  
Несколько `LevelSpawnPoint` на целевом уровне → разные `portal_id` (пример: `cave_entrance` и `cave_side` в `cave_test.tscn`).

**Схема связки**

```
Уровень A                          Уровень B
  Zone "В пещеру"  ──arrival_portal_id=cave_entrance──►  Spawn cave_entrance
  Zone "Боковой вход" ──arrival_portal_id=cave_side────►  Spawn cave_side
  Spawn main_from_cave ◄──arrival_portal_id=main_from_cave──  Zone "На поляну"
```

Autoload **`LevelTravelManager`**: смена сцены, появление у маркера, снимок инвентаря/статов между переходами, **экран загрузки** до применения состояния мира (без «мига» врагов).

На корне каждого уровня с `main_game_bootstrap.gd` задайте **`level_save_key`** = путь этой сцены (например `res://scenes/levels/cave_test.tscn`). В зонах перехода указывайте целевую сцену через **`res://…`**, не `uid://`, чтобы ключи кэша совпадали.

**Пример в проекте:** `main` → `LevelPortals` (зона к пещере ~(8, 8)); `scenes/levels/cave_test.tscn` + `cave_world.tscn` — выход обратно.

**Состояние мира по уровням:** autoload `LevelWorldCache` — ключ = **`level_save_key`** или нормализованный путь `.tscn` (любое число уровней). При уходе — снимок; при возврате/сейве — восстановление. В сейв попадают все **посещённые** сцены (`extension_data.levels`). Сохраняются автоматически:

| Что | Как |
|-----|-----|
| Срубленная добыча | `Harvestable` + `persist_id` (или путь узла) |
| Убитые враги | `EnemyBody` + `persist_id`, группа `enemy` |
| Дроп на земле | группа `dropped_items` |
| Сундуки / станции | группы `persist_chest`, `persist_crafting_station` |

Новые уровни подключаются без правок кода, если соблюдён чеклист в `scenes/levels/README.md`.

## Геймплей: задумка (черновик)

Здесь — не код, а **договорённости по смыслу**: откуда берутся ресурсы, как мир не «высасывается» за час, нужна ли ферма. Когда зафиксируете питч — подчистите текст; пока это рабочая опора для чеклиста выше.

### О чём игра

- **Рабочая гипотеза:** выживание и обустройство в месте после катастрофы / среди руин (остров, сектор карты — на выбор) — добыча, крафт, давление статов, со временем угрозы и **ясная цель** (сигнал, эвакуация, укреплённая база, ключевой артефакт). Название *EchoWreck* можно связать с эхом разрушения, остатками техники, аномалией — **одну фразу лора** лучше записать отдельно и держать в описаниях предметов и локаций.
- **Тон:** «сбор + станции + прогресс инструмента» в центре; бой и ночь **поддерживают** цикл (лут, риск, темп), а не вытесняют добычу полностью.

### Где добываются ресурсы (слои)

| Слой | Примеры | Роль в петле |
|------|---------|----------------|
| **Окружение** | деревья, камень, руда, кусты, грибы — по сеттингу | базовый цикл: инструмент → материал → крафт |
| **Опасность** | враги, элитные узлы | редкие материалы, скачок прогрессии, трата расходников |
| **Следы цивилизации** | сундуки, обломки, брошеные станции | крупный контролируемый лут, «история» мира |
| **Переработка** | костёр, верстак, кузница, ткачество | уже в игре: сырьё → полуфабрикат → предмет |

Важно, чтобы игрок **визуально или по квесту** понимал, куда идти за следующим слоем (дым, свет, тропа, мост, руины), а не только рандомно шарил по полю.

### Как возвращать ресурсы (возобновление)

Можно комбинировать, но для прототипа полезно **выбрать одну доминирующую идею**:

1. **Респавн в мире** — узел добычи исчезает или превращается в «пень» / пустую жилу и через игровые сутки / реальные N минут снова даёт ресурс. Плюс: одна карта не кончается; минус: таймеры, поведение вне экрана, анти‑абуз (радиус базы).
2. **Конечные залежи + новые точки** — на старте мало руды, новые жилы открываются исследованием, квестом или «провалом» в другой слой карты. Плюс: сценарий; минус: больше ручного контента.
3. **Производство у игрока** — переработка мусора, грибница, сад, разведение. Плюс: привязка к базе; минус: отдельные системы и баланс.

Для первого **играбельного горизонта** обычно хватает: **простой респавн** для растительности/мелкого сбора **или** одной лёгкой формы посадки без сезонов.

### Фермерство: нужно ли

**Не обязательно** для полноценного survival, если голода/жажды закрывают дикий сбор, крафт еды и лут. Ферма **оправдана**, если цель — долгие сессии у базы и ощущение «я это вырастил».

| Объём | Суть | Когда выбирать |
|--------|------|----------------|
| **Нет фермы** | только сбор, охота, респавн кустов, еда с врагов | быстрый MVP, фокус на исследовании и бою |
| **Лёгкая грядка** | 1–3 слота, один таймер роста, опционально «полить раз в N» | нужен стабильный источник еды/трав без симуляции почвы |
| **Полная ферма** | сезоны, удобрения, типы культур | только если это **столп** игры, не побочка |

**Практично для EchoWreck:** начать **без полноценной фермы**, дать **возобновление диких узлов** (ягоды, деревья с таймером или саженец→дерево одним типом). Грядки добавить **после** сохранений, боя и устойчивого крафта — если всё ещё не хватает источника еды.

### Связка с кодом (ориентир)

- Добыча уже на `Harvestable` + `LootTable`; возобновление — новые узлы вроде **«зона респавна»**, **таймер на пне** или **состояние жилы** без переписывания `ItemData`.
- Лёгкая ферма — отдельный объект (`GardenPlot` и т.п.): слот посадки принимает семя из инвентаря, по таймеру выдаёт предмет.

## Идея «полноценной игры» (крупные блоки)

Ниже не чеклист на один вечер, а ориентиры, из которых потом нарезаются маленькие пункты выше.

1. **Петля выживания** — регулярные траты статов, понятные способы их закрывать (еда, вода, отдых, укрытие).
2. **Петля прогрессии** — крафт лучше инструментов, броня, доступ к новым рецептам/биомам.
3. **Петля риска** — враги или опасность среда/ночь, смерть со смыслом (лут теряется / чекпоинт).
4. **Петля цели** — квест, босс, эвакуация или база: чтобы игрок знал, зачем копать и крафтить.
